## .git文件

當我們在一個目錄中執行：

```bash
git init
```

Git 會在當前目錄下建立一個 `.git` 目錄。

很多時候，我們只會使用：

```bash
git add
git commit
git status
git branch
git checkout
git merge
```

但是很少會真正看 `.git` 裡面到底保存了什麼。

實際上，`.git` 目錄就是 Git 倉庫的核心。

工作區裡的代碼可以刪除、修改、重新 checkout，但是 `.git` 目錄中保存了 Git 對這個項目的完整理解，包括：

- 提交歷史
- 分支位置
- 暫存區內容
- 對象數據
- 遠程倉庫配置
- HEAD 當前指向
- tag 信息
- hook 腳本

所以 `.git` 的本質是：

> Git 用一組文件和目錄，描述一個版本控制系統的狀態。

## 建立模型

在分析 `.git` 之前，可以先想幾個問題：

- Git 如何知道當前在哪個分支？
- Git 如何保存一次 commit？
- Git 如何知道哪些文件被 add 了？
- Git 如何表示分支？
- Git 如何從 commit 找到完整的文件快照？
- Git 如何知道遠程倉庫地址？
- Git 如何恢復歷史版本？

可以把 `.git` 想像成一個小型數據庫。

這個數據庫主要保存三類信息：

```text
狀態信息
對象信息
引用信息
```

例如：

```text
.git/HEAD
```

表示當前工作區指向哪裡。

```text
.git/objects
```

保存 Git 中最核心的對象數據。

```text
.git/refs
```

保存分支、tag 等引用。

```text
.git/index
```

保存暫存區的狀態。

所以 `.git` 的核心思想是：

> 用 object 保存內容，用 ref 保存名字，用 HEAD 表示當前位置，用 index 表示即將提交的內容。

## .git的基本結構

一個剛初始化的 Git 倉庫中，`.git` 目錄通常長這樣：

```text
.git
├── HEAD
├── config
├── description
├── hooks
├── index
├── info
├── objects
└── refs
```

如果已經有過提交，可能還會看到：

```text
.git
├── COMMIT_EDITMSG
├── FETCH_HEAD
├── ORIG_HEAD
├── logs
├── packed-refs
└── objects/pack
```

這些文件看起來很多，但是可以分成幾個核心部分：

```text
HEAD        當前指向
config      倉庫配置
index       暫存區
objects     對象數據庫
refs        分支和tag
logs        引用變更記錄
hooks       Git事件腳本
```

## HEAD

`.git/HEAD` 用來表示當前工作區指向哪裡。

查看它：

```bash
cat .git/HEAD
```

通常會看到：

```text
ref: refs/heads/main
```

這表示：

當前 HEAD 指向 `refs/heads/main`，也就是 main 分支。

此時 HEAD 並不是直接指向某個 commit，而是指向一個分支引用。

再查看 main 分支：

```bash
cat .git/refs/heads/main
```

可能得到：

```text
a3f5c9d8e7b2c1a9f0e6d4c3b2a190876543abcd
```

這個 hash 就是一個 commit object 的 ID。

所以正常分支狀態下，關係是：

```text
HEAD -> refs/heads/main -> commit object
```

## detached HEAD

如果執行：

```bash
git checkout a3f5c9d
```

此時再查看 `.git/HEAD`：

```bash
cat .git/HEAD
```

可能會看到：

```text
a3f5c9d8e7b2c1a9f0e6d4c3b2a190876543abcd
```

這時 HEAD 直接指向 commit，而不是指向分支。

這種狀態叫做 detached HEAD。

可以理解為：

```text
HEAD -> commit object
```

而不是：

```text
HEAD -> branch -> commit object
```

這時如果提交新的 commit，Git 可以生成新的提交，但是沒有分支名字穩定地指向它。

所以 detached HEAD 的風險是：

> 新 commit 可能變成沒有引用指向的孤立提交，後續容易被垃圾回收清理。

## config

`.git/config` 保存當前倉庫的本地配置。

查看它：

```bash
cat .git/config
```

可能看到：

```ini
[core]
    repositoryformatversion = 0
    filemode = true
    bare = false
    logallrefupdates = true

[remote "origin"]
    url = git@github.com:user/repo.git
    fetch = +refs/heads/*:refs/remotes/origin/*

[branch "main"]
    remote = origin
    merge = refs/heads/main
```

其中：

- `core` 表示 Git 倉庫的基本配置。
- `remote "origin"` 表示遠程倉庫地址。
- `branch "main"` 表示 main 分支和遠程分支的追蹤關係。

所以當我們執行：

```bash
git remote -v
```

Git 其實就是讀取 `.git/config` 裡面的 remote 信息。

當我們執行：

```bash
git push
```

Git 會根據 `.git/config` 中當前分支對應的 remote 和 merge 配置，決定要推送到哪裡。

## objects

`.git/objects` 是 Git 最核心的目錄。

Git 中幾乎所有重要內容都以 object 的形式保存。

主要有四種 object：

```text
blob    文件內容
tree    目錄結構
commit  一次提交
tag     標籤對象
```

可以把 Git object 想像成一個內容尋址的數據庫。

也就是說：

> Git 不是根據文件名保存內容，而是根據內容計算 hash，然後用 hash 作為對象 ID。

例如一個文件內容是：

```text
hello git
```

Git 會根據 object 類型、內容長度和內容本身計算 hash，然後把對象保存到 `.git/objects` 中。

## blob object

blob object 保存的是文件內容。

例如建立一個文件：

```bash
echo "hello git" > hello.txt
git add hello.txt
```

此時 Git 會為 `hello.txt` 的內容建立一個 blob object。

可以使用：

```bash
git hash-object hello.txt
```

得到類似：

```text
8ab686eafeb1f44702738c8b0f24f2567c36da6d
```

這個 hash 對應一個 blob object。

但是 blob object 只保存文件內容，不保存文件名。

也就是說，blob object 知道：

```text
hello git
```

但是不知道：

```text
hello.txt
```

文件名保存在 tree object 裡。

## tree object

tree object 保存的是目錄結構。

它記錄：

- 文件模式
- 文件名
- 文件對應的 blob hash
- 子目錄對應的 tree hash

例如一次提交中的目錄可能表示為：

```text
100644 blob 8ab686eafeb1f44702738c8b0f24f2567c36da6d    hello.txt
040000 tree e3f2a1c0d9b8a7654321abcdef9876543210abcd    src
```

這表示：

```text
hello.txt -> blob object
src       -> tree object
```

所以 tree object 的作用是：

> 把文件名和文件內容 hash 組織成一棵目錄樹。

## commit object

commit object 表示一次提交。

查看某個 commit：

```bash
git cat-file -p HEAD
```

可能看到：

```text
tree 6dcb09b5b57875f334f61aebed695e2e6f1c9f2e
parent a3f5c9d8e7b2c1a9f0e6d4c3b2a190876543abcd
author user <user@example.com> 1776748470 +0800
committer user <user@example.com> 1776748470 +0800

add hello.txt
```

其中：

```text
tree
```

表示這次提交對應的完整文件快照。

```text
parent
```

表示上一個 commit。

```text
author
committer
```

表示作者和提交者信息。

最後一行是 commit message。

所以 commit object 的本質是：

> 指向一棵 tree，並指向它的父 commit。

多個 commit 連起來，就形成 Git 的提交歷史。

```text
commit C -> commit B -> commit A
```

## tag object

tag 有兩種常見形式：

```text
lightweight tag
annotated tag
```

lightweight tag 本質上就是一個 ref，直接指向某個 commit。

annotated tag 則會生成一個 tag object。

查看 tag：

```bash
git cat-file -p v1.0.0
```

可能看到：

```text
object a3f5c9d8e7b2c1a9f0e6d4c3b2a190876543abcd
type commit
tag v1.0.0
tagger user <user@example.com> 1776748470 +0800

release version 1.0.0
```

tag object 會保存：

- 指向的對象
- 對象類型
- tag 名稱
- tagger 信息
- tag message

所以 annotated tag 更像是一個正式的發布記錄。

## refs

`.git/refs` 保存引用。

常見結構：

```text
.git/refs
├── heads
│   └── main
├── remotes
│   └── origin
│       └── main
└── tags
    └── v1.0.0
```

其中：

```text
refs/heads/main
```

表示本地 main 分支。

```text
refs/remotes/origin/main
```

表示遠程 origin/main 分支在本地的記錄。

```text
refs/tags/v1.0.0
```

表示 tag。

分支的本質非常簡單：

> 分支就是一個保存 commit hash 的文件。

例如：

```bash
cat .git/refs/heads/main
```

輸出：

```text
a3f5c9d8e7b2c1a9f0e6d4c3b2a190876543abcd
```

這表示 main 分支目前指向這個 commit。

當你在 main 分支上提交新 commit 時，Git 只是把 `.git/refs/heads/main` 裡面的 hash 更新成新的 commit hash。

所以分支切換的本質是：

> 改變 HEAD 指向的 ref，並把工作區更新成對應 commit 的 tree。

## index

`.git/index` 是暫存區。

當我們執行：

```bash
git add hello.txt
```

Git 會做兩件事：

第一，根據文件內容生成 blob object，保存到 `.git/objects`。

第二，把文件路徑、文件模式、blob hash 等信息寫入 `.git/index`。

所以 index 表示的是：

> 下一次 commit 將要提交的文件快照。

查看 index 內容可以使用：

```bash
git ls-files --stage
```

輸出可能是：

```text
100644 8ab686eafeb1f44702738c8b0f24f2567c36da6d 0    hello.txt
```

這表示：

```text
文件模式: 100644
blob hash: 8ab686eafeb1f44702738c8b0f24f2567c36da6d
stage: 0
文件名: hello.txt
```

此時如果執行：

```bash
git commit -m "add hello.txt"
```

Git 會根據 index 中的內容生成 tree object，再生成 commit object。

所以從 add 到 commit 的流程是：

```text
working tree -> index -> tree object -> commit object
```

## logs

`.git/logs` 保存引用變更記錄。

常見文件：

```text
.git/logs/HEAD
.git/logs/refs/heads/main
```

查看 HEAD 的變更：

```bash
cat .git/logs/HEAD
```

可能看到：

```text
0000000000000000000000000000000000000000 a3f5c9d8e7b2c1a9f0e6d4c3b2a190876543abcd user <user@example.com> 1776748470 +0800    commit (initial): add hello.txt
```

這就是 reflog 的底層數據。

當我們執行：

```bash
git reflog
```

Git 讀取的就是 `.git/logs` 中的內容。

reflog 很有用，因為即使你 reset 或 checkout 到其他 commit，也可能通過 reflog 找回之前的位置。

例如：

```bash
git reset --hard HEAD~1
```

如果想找回被 reset 掉的 commit，可以使用：

```bash
git reflog
git reset --hard <old_commit_hash>
```

所以 logs 的作用是：

> 記錄 ref 曾經指向過哪裡，幫助恢復誤操作。

## hooks

`.git/hooks` 保存 Git hook 腳本。

例如：

```text
pre-commit
commit-msg
pre-push
post-merge
```

新建倉庫時，Git 會生成一些 `.sample` 文件：

```text
pre-commit.sample
commit-msg.sample
pre-push.sample
```

如果想啟用 hook，需要去掉 `.sample` 後綴。

例如：

```bash
mv .git/hooks/pre-commit.sample .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

hook 的作用是：

> 在 Git 的某些事件發生前後，自動執行腳本。

常見用途包括：

- commit 前跑格式化
- commit message 校驗
- push 前跑測試
- merge 後更新依賴

例如 `pre-commit`：

```bash
#!/bin/sh

npm test
```

這表示每次 commit 前都會先執行測試。

## packed-refs

當分支或 tag 很多時，Git 不一定會把每個 ref 都保存成單獨文件。

它可能會把多個 ref 壓縮到：

```text
.git/packed-refs
```

內容可能是：

```text
# pack-refs with: peeled fully-peeled sorted
a3f5c9d8e7b2c1a9f0e6d4c3b2a190876543abcd refs/tags/v1.0.0
b4e6d9c8a1f2e3d4c5b6a79876543210abcdef12 refs/tags/v1.1.0
```

所以查找 ref 時，Git 可能會同時查：

```text
.git/refs
.git/packed-refs
```

這也是為什麼有時候你在 `.git/refs/tags` 裡看不到某個 tag，但是 `git tag` 仍然能看到它。

## objects/pack

一開始，Git object 通常以 loose object 的形式保存。

例如 hash 是：

```text
8ab686eafeb1f44702738c8b0f24f2567c36da6d
```

Git 會保存成：

```text
.git/objects/8a/b686eafeb1f44702738c8b0f24f2567c36da6d
```

前兩位作為目錄名，後面作為文件名。

但是如果 object 很多，這種方式效率不高。

Git 會把多個 object 壓縮成 packfile：

```text
.git/objects/pack
├── pack-xxxx.pack
└── pack-xxxx.idx
```

其中：

```text
.pack
```

保存壓縮後的 object 數據。

```text
.idx
```

保存索引，用來快速查找 object。

當執行：

```bash
git gc
```

Git 可能會清理無用對象，並把 loose object 壓縮成 packfile。

所以 `objects/pack` 的作用是：

> 提高大量 object 存儲和讀取的效率。

## Git如何保存一次提交

現在把上面的內容串起來。

假設我們執行：

```bash
echo "hello git" > hello.txt
git add hello.txt
git commit -m "add hello.txt"
```

Git 內部大致會發生：

第一步，生成 blob object：

```text
hello.txt content -> blob object
```

第二步，更新 index：

```text
hello.txt -> blob hash
```

第三步，commit 時根據 index 生成 tree object：

```text
tree -> hello.txt -> blob hash
```

第四步，生成 commit object：

```text
commit -> tree hash
commit -> parent commit
commit -> author
commit -> message
```

第五步，更新當前分支 ref：

```text
refs/heads/main -> new commit hash
```

第六步，HEAD 仍然指向 main：

```text
HEAD -> refs/heads/main
```

整體關係是：

```text
HEAD
  |
  v
refs/heads/main
  |
  v
commit object
  |
  v
tree object
  |
  v
blob object
```

## Git實戰

### 第一步

建立一個新的 Git 倉庫：

```bash
mkdir git-internal-demo
cd git-internal-demo
git init
```

查看 `.git` 目錄：

```bash
ls -la .git
```

可以看到：

```text
HEAD
config
description
hooks
info
objects
refs
```

### 第二步

查看 HEAD：

```bash
cat .git/HEAD
```

輸出：

```text
ref: refs/heads/main
```

如果你的 Git 默認分支是 master，可能會看到：

```text
ref: refs/heads/master
```

這表示當前 HEAD 指向 main 或 master 分支。

### 第三步

建立文件並 add：

```bash
echo "hello git" > hello.txt
git add hello.txt
```

查看暫存區：

```bash
git ls-files --stage
```

輸出類似：

```text
100644 8ab686eafeb1f44702738c8b0f24f2567c36da6d 0    hello.txt
```

這裡的 hash 就是 hello.txt 對應的 blob object。

查看 object 類型：

```bash
git cat-file -t 8ab686eafeb1f44702738c8b0f24f2567c36da6d
```

輸出：

```text
blob
```

查看 object 內容：

```bash
git cat-file -p 8ab686eafeb1f44702738c8b0f24f2567c36da6d
```

輸出：

```text
hello git
```

### 第四步

提交文件：

```bash
git commit -m "add hello.txt"
```

查看 commit：

```bash
git cat-file -p HEAD
```

輸出類似：

```text
tree 6dcb09b5b57875f334f61aebed695e2e6f1c9f2e
author user <user@example.com> 1776748470 +0800
committer user <user@example.com> 1776748470 +0800

add hello.txt
```

第一行的 tree 表示這次提交對應的目錄快照。

查看 tree：

```bash
git cat-file -p 6dcb09b5b57875f334f61aebed695e2e6f1c9f2e
```

輸出類似：

```text
100644 blob 8ab686eafeb1f44702738c8b0f24f2567c36da6d    hello.txt
```

這說明：

```text
commit -> tree -> blob
```

### 第五步

查看分支 ref：

```bash
cat .git/refs/heads/main
```

輸出：

```text
<commit_hash>
```

這個 hash 和下面命令的輸出是一樣的：

```bash
git rev-parse HEAD
```

這說明：

```text
HEAD -> refs/heads/main -> commit_hash
```

### 第六步

修改文件：

```bash
echo "hello git again" > hello.txt
git add hello.txt
git commit -m "update hello.txt"
```

查看提交歷史：

```bash
git log --oneline
```

輸出：

```text
b4e6d9c update hello.txt
a3f5c9d add hello.txt
```

查看新的 commit：

```bash
git cat-file -p HEAD
```

會看到：

```text
tree <new_tree_hash>
parent <old_commit_hash>
author ...
committer ...

update hello.txt
```

這裡多了一行：

```text
parent <old_commit_hash>
```

表示新的 commit 指向上一個 commit。

所以 Git 的歷史不是保存差異文本，而是保存一個個 commit object，每個 commit 指向自己的 tree，並通過 parent 連成歷史鏈。

## 常見誤解

### .git是不是只保存diff？

不是。

Git 的 commit object 指向的是一棵 tree，tree 表示一次完整的文件快照。

Git 在展示差異時，會比較兩個 tree 之間的不同。

所以更準確地說：

> Git 主要保存快照，而不是只保存 diff。

### 分支是不是一份完整代碼？

不是。

分支本質上只是一個 ref 文件，裡面保存一個 commit hash。

例如：

```text
.git/refs/heads/main
.git/refs/heads/dev
```

它們只是兩個名字，分別指向不同的 commit。

所以建立分支很快，因為 Git 只需要新增一個引用文件。

### git add是不是只是標記文件？

不只是。

`git add` 會把文件內容寫入 object database，並更新 index。

也就是：

```text
working tree -> object database
working tree -> index
```

所以 add 之後，即使你又修改了工作區文件，index 裡保存的仍然是 add 那一刻的版本。

### 刪除.git會怎樣？

如果刪除 `.git`：

```bash
rm -rf .git
```

那麼這個目錄就不再是一個 Git 倉庫。

工作區文件還在，但是：

- 提交歷史消失
- 分支信息消失
- tag 信息消失
- 遠程配置消失
- reflog 消失
- hooks 消失

所以 `.git` 是 Git 倉庫真正的核心數據。

## 總結

`.git` 目錄可以從四個核心概念理解：

```text
HEAD    當前位置
refs    名字到commit的映射
objects 真正的內容數據庫
index   下一次提交的快照
```

一次提交的核心鏈路是：

```text
working tree
    |
    v
index
    |
    v
tree object
    |
    v
commit object
    |
    v
refs/heads/main
```

Git 的很多操作本質上都是在修改這些文件：

```text
git add      -> 寫 objects，更新 index
git commit   -> 生成 tree 和 commit，更新 ref
git branch   -> 新增 ref
git checkout -> 修改 HEAD，更新工作區
git reset    -> 移動 ref，可能更新 index 和工作區
git reflog   -> 查看 logs
git gc       -> 清理和壓縮 objects
```

所以學 `.git` 的意義不是為了手動修改它，而是為了真正理解：

> Git 不是一組神秘命令，而是一個基於 object、ref、index 和 HEAD 組成的版本控制數據庫。
